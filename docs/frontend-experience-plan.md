# 前端体验升级方案（待逐步验证）

## 范围与现状

本地分支：`feat/frontend-animations-social`。在现有前端基础上增加结算动画、页面过场、头像、房间聊天和自定义表情包，完成后统一提交 PR。

2026-11-09 已阅读前端入口、视图、状态层及通信协议；在本地离线模式浏览登录、大厅、建桌、等待室与牌桌，并查看 1440×900 横屏和 390×844 竖屏。尚未完成真实双人联机、账号战绩和管理页的浏览器验收。本轮仅形成方案，不改业务代码。

现有前端是原生 ESM、HTML、CSS，无构建依赖。背景为扑克主题图片、生活照片及等待室照片轮播；牌桌为 CSS 绿绒木边椭圆。已有行动高亮、牌背、结算明细浮层、toast 和小幅弹出效果。大厅头像目前只是黑桃占位，协议里没有头像、聊天、表情功能。

## 美术方向：熟人牌局 · 墨绿暖金

- 保留现有照片与牌桌，延续朋友聚会的气氛；优先统一界面材质和层级。
- 主色采用现有墨绿 `#17402f` / `#0b2118`，面板采用炭黑 `#171b21`，暖金 `#f6c453` 用于重点。收益与损失同时用文字、正负号和颜色表达。
- 公共牌、筹码、行动按钮保持最高可读性。照片压暗、面板适当增加不透明度，修复浅色面板上的低对比文字。
- 头像采用统一圆形框、简洁插画和少量配色，先做内置头像选择及保存；表情沿用同一套角色与描边。美术资产制作放在规则与布局验证之后。
- 操作反馈轻快，结算略有仪式感。避免持续闪烁和大范围粒子遮挡牌桌。

## 动画设计

| 场景 | 表现 | 建议时长与约束 |
| --- | --- | --- |
| 页面进入 | 内容淡入、上移 6–10px；离开及时清理 | 200–280ms，快速连续切换不能留下隐藏页面按钮 |
| 弹窗与聊天抽屉 | 背景渐暗、面板轻微位移 | 160–220ms，支持关闭、焦点管理与键盘操作 |
| 发手牌 | 牌背从桌心依次滑入，自己的牌随后揭示 | 单张 180–240ms，后续错开约 60ms |
| 公共牌 | 只对新增牌依次翻开 | 单张 220–280ms，旧牌不随状态更新重播 |
| 跟注与加注 | 小组筹码从座位移向下注区，数字直接显示正确值 | 250–350ms，不等待动画才更新金额 |
| 行动轮转 | 头像框短暂亮起，倒计时清晰显示 | 一次短脉冲；低时间使用文字提示 |
| 胜利 | 获奖座位高亮、筹码归集、净收益数字出现、少量金色光点 | 主流程约 1.2–1.6s，点击可跳过 |
| 失败 | 结算面板柔和进入，净损失清晰出现 | 500–800ms，不震屏、不反复强调损失 |
| 平局与旁观 | 中性结算；显示各玩家结果 | 不把退款误报成胜利；旁观不显示“你输了” |
| 表情 | 头像旁短暂弹出后淡出 | 约 2s，限频；不覆盖公共牌、筹码与行动区 |

结算以服务端结果为依据：获奖位置看各池派彩；自己的胜负看净变化。多人获奖、边池、退款、零净变化、弃牌获胜分别处理，不依赖“最大派彩金额者就是唯一赢家”的假设。

## 先处理的结构问题

1. `.card` 同时用于面板与扑克牌，后定义的白色牌面样式污染等待室面板；`index.html` 已有局部补丁，但没有彻底区分。先隔离样式用途，统一面板可读性。
2. `TableView.renderResult()` 每次渲染都会重建浮层并重置计时器。按房间及 handId 去重，固定本手结算数据；重连不重播历史庆祝；离桌销毁计时器和动画。
3. 前端 `RESULT_HOLD_MS=4500`，服务端默认 `SETTLE_HOLD_MS=2500`。结算不能挡住下一手操作：下一手到来立即收起阻挡层，明细可从记录查看；动画不能拖慢服务器状态。
4. 公共牌变化目前会重建全部牌位。新增动画需要保留稳定节点，仅播放新增牌效果；座位与浮层也不能因倒计时或聊天更新反复重播。
5. 手机竖屏当前需要滚动才能看全座位，下注预设横向滚动。加入头像前先控制座位高度和操作区占用，保证当前行动者与关键牌局信息可见。
6. 页面切换要保持现有隐藏页面 `display:none` 的约束；动画结束与取消均有清理路径。

## 头像与社交功能

### 头像

第一版提供统一内置头像，以稳定 `avatarId` 保存到账号资料，并在大厅、等待室、牌桌、聊天中一致显示。缺失或非法 ID 使用默认头像，离线模式保存本地选择。头像不代替昵称与位置标签。

### 房间聊天

等待室和牌桌共用本房间消息流，桌面侧栏、手机底部抽屉；收起时仅显示未读提示和短气泡。第一版以房间聊天为范围，不扩展到私信、语音或全站频道。

需要新增服务端协议：房间成员身份校验、服务端消息 ID 和时间、长度限制、发送限频、失败反馈与客户端去重。显示纯文本；只在用户已滚到底部时自动滚动。离开房间后停止接收；重连不重复显示消息。聊天与牌局日志分开。

### 自定义表情包

先用内置表情验证选择、发送、接收和气泡定位，再增加用户图片导入。目标是其他玩家实际可见，不做仅发送者可见的本地假功能。

图片需独立上传与存储接口、格式及大小校验、缩放和数量上限，聊天事件只引用表情资源 ID。首版建议 PNG/JPEG/WebP 静态图片，不直接接受 SVG/HTML 或任意外链。是否支持 GIF、整包导入与资源持久保存，在进入此阶段时确认产品需求。

## 技术约束与测试方式

- 优先 CSS transform / opacity 与浏览器原生动画能力，保持零构建结构；需要复杂美术时再增加图片资产，不预先引入大动画库。
- 动画只是状态变化的呈现。服务器时间、筹码、合法操作与私有手牌始终由现有逻辑控制。
- 所有效果支持 `prefers-reduced-motion`；切后台、退出视图、重连、下一手开始时能结束或取消。
- 固定输入场景覆盖胜、负、平、多人获奖、退款、旁观，便于重复评审。对去重、协议、房间隔离和上传校验补充有意义的自动检查。
- 浏览器检查桌面 1440×900、手机 390×844 / 360×800 及手机横屏；最终结合真实两客户端和用户设备验证。基线跑通后才用测试结果判断新增改动。
